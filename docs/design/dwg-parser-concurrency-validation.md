# DWGParser v10：并发优化与消融验证

核对日期：2026-09-10。当前源码已实现并通过 T0202 单文件实导；未启动批量导入或 55 题评测。

## 结论

T0202 服务端导入从 v9 的 **291.452 秒降到 170.268 秒**，减少 **41.6%**。主要变化在 Sheet 图像请求的重叠执行：包含渲染、选区和 Markdown 整理的阶段从 **143.553 秒降到 48.659 秒**。

本轮只修改四个生产文件，净增 19 行，没有新增外部依赖或配置字段。新增代码用于并发、请求上下文和队列补位；删除了完整 JSON 布局下已经重复的建目录逻辑。

## 分别保留了什么，依据是什么

| 项目 | 原行为 / 复现问题 | 保留的最小改动 | 验证 |
|---|---|---|---|
| Sheet 区域识别 | 19 个候选逐个等待渲染和网络返回 | 使用现有 `vlm.max_concurrent`，每任务继承上下文，按原候选序归并 | 合成固定返回对照、真实 T0202 固定返回回放均逐字节一致；实导区域调用峰值 4 |
| 异步模型接口 | 同步模型及统计对象不适合直接共享给新线程 | 复用已有 `run_async` 与异步 vision 接口，在共享循环内发请求 | 上下文、token 聚合、同循环并发测试通过；没有改提示与选择规则 |
| 渲染失败缓存 | 四个等待线程可在锁外同时通过检查，重复初始化失败的渲染器 | 把失败检查移入原有渲染锁 | 复现中初始化从 4 次变 1 次；错误语义保持不变 |
| 摘要 worker 补位 | A 忙碌后提交 B，上限 4 却可能只保留 1 个 worker | 按忙碌数与排队数补位，仍受原上限约束 | 原事件样例修前超时、修后通过；上限、FIFO、空闲复用和异常/取消清理测试通过 |
| JSON 目录创建 | Sheet 目录已创建，写 drawing 时又做一遍 mkdir | 删除目录缓存及重复 mkdir | 单次目录创建断言与正式入库、字节保全验证通过 |

渲染仍使用原 `_RENDER_LOCK`。并发的是区域请求及其与渲染的重叠，不是四路 Matplotlib。区域并发上限属于一次 DWG 构建，不构成多个导入与所有摘要调用共享的全服务模型总额度。

## 消融如何保证内容没有随优化改变

先用同一份合成输入比较冻结 v9 的串行处理与 v10 的乱序并发返回：全部 Sheet 描述、7 份 Markdown、9 份 JSON 一致。错误隔离、空选区、被拒绝候选、无 VLM 和渲染失败等情况单独验证。

随后，正式导入 T0202 时在实验目录记录 19 份区域返回。固定原生 DWG 和这 19 份返回，分别回放冻结 v9 串行与冻结 v10 四并发，不再调用 VLM 或 ODA。结果为：

- 两者均生成 19 个 Sheet、23 份 Markdown、21 份完整 JSON。
- Sheet 描述、顺序及全部 Markdown / JSON 字节一致，并与实际发布产物相同。
- 37,749 个原对象和全部顶层字段保全；2,145 个正文迁移字段的来源和实例覆盖验证通过。
- 原始 DWG、代码、配置和记录返回在回放前后均未改变。

因此，上次实导 24 份 Markdown、本次 23 份的差异，不是并发或提取逻辑改动引入：固定本次返回后，旧代码也生成 23 份。该结论不评价两次 VLM 返回哪一次更正确。

所有对照和计时包装都在测试或本地实验目录中完成，生产没有增加实验开关、缓存框架或区域启发式。

## 实际耗时与调用边界

| 阶段 | v9 秒 | v10 秒 |
|---|---:|---:|
| LibreDWG 转换与规范化 | 4.497 | 4.574 |
| Sheet 渲染、选区与 Markdown 整理 | 143.553 | 48.659 |
| 完整 JSON 生成 | 2.403 | 2.349 |
| JSON 校验与登记 | 0.522 | 0.498 |
| Markdown 摘要批次 | 135.900 | 110.409 |
| Markdown 索引与等待 | 4.048 | 3.048 |
| **完整请求，含其余开销** | **291.452** | **170.268** |

本次 19 次区域调用全部成功，峰值 4；调用累计时长为 99.449 秒，重叠区间并集为 39.881 秒。并发时不能把调用累计时长当墙钟时间，也不能把渲染包装中的锁等待当成并行渲染收益。

摘要实际为 23 次文件摘要和 19 次目录摘要，Sheet DAG 峰值 4。原生 VLM 统计为 61 次，等于 19 + 23 + 19；实际消息白名单只含 context Markdown。向量存储精确对应 23 份 Markdown，JSON 向量为 0。分页读取、JSON grep→read、原生带向量导包与源哈希检查通过。

这是每版本一次实导的端到端对照。两次模型返回、输入分段和网络耗时存在差异，且区域并发与 worker 修复一起启用；**不能将摘要阶段或总耗时差值单独归因于 worker 补位修复**。该修复的独立依据是已复现的排队缺口和固定事件回归。

## 暂不引入的改动

| 候选 | 本轮处理 |
|---|---|
| 删除单 Markdown Sheet 的第二级摘要 | 不删除：文件摘要与带文件导航结构的目录摘要有不同消费者，尚无质量对照证明可合并 |
| 增加 Markdown 读取缓存或摘要去重 | 不增加：基线 24 份 MD 共约 76 KB，且没有字节相同的重复文件，没有可验证收益 |
| 并行渲染或多进程渲染 | 不增加：现有库的共享状态需要锁；没有独立证明安全和收益 |
| 自动同时导入多份 DWG | 本轮不启用：尚未验证跨导入的模型额度和内存协调，不能把单份 DWG 的上限误认为全局上限 |
| 减少图像选择或摘要调用 | 不改规则：会涉及内容质量，需后续固定题集对照 |
