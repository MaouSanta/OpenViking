# DWGParser 10.2：固定输入消融与代码精简

2026-09-14。基线为本轮开始时的 10.2 工作区版本：JSON 原文字段完整保留，Markdown 保持现有内容。

本轮保留两项结果等价的优化，并删除没有调用入口的旧生成器。监控图的确定性处理耗时中位数从 **39.28 秒降至 22.12 秒，减少 43.7%**；T0202 的无 VLM 对照从 **4.98 秒降至 4.14 秒，减少 16.8%**。所有受测产物逐文件哈希相同，212 项相关测试通过。

这些数值只覆盖 Sheet/Markdown 构建及 JSON 组织、序列化，不包含源文件转换、规范化、渲染、VLM、摘要、发布及 Embedding。不能把它们解释为完整导入提速比例，也没有重新运行 55 题。

## 剖析发现

监控 DWG 的 68,781 个原生对象、10 个固定区域响应用于 cProfile。Sheet 构建产生约 6.21 亿次函数调用：

- 选项框/单选框识别反复扫描远处线段，并在几何过滤前比较来源字符串。剖析中 `repr` 调用约 5516 万次。
- 图框分配阶段，同一边界的容差被重复计算；Sheet 剖析中的 `tolerance` 调用约 219 万次。
- JSON 阶段，序列化与几何归属仍占主要部分；重复构建对象关系表约占 0.58 秒，空间排序约占 0.22 秒，均为带 profiler 开销的数值。

剖析耗时只用于定位热点。下表使用不启用 profiler 的重复测量，输入加载和哈希校验均在计时区间之外。

## 消融设计与结果

监控图保持实际记录的十个 VLM 区域响应固定，使用占位图像，不调用模型。依次测量基线、单项 A、单项 B、组合 AB，各三次；第二轮倒序执行以减小顺序影响。全部测量串行运行。

| 变体 | 唯一变化 | Sheet/MD 中位耗时 | 总中位耗时 | 相对基线减少 |
|---|---|---:|---:|---:|
| 基线 | 无 | 34.70 s | 39.28 s | — |
| A | 标记检测跳过无用线段计算 | 19.70 s | 24.22 s | 38.4% |
| B | 复用单个图框的容差 | 31.73 s | 36.30 s | 7.6% |
| AB | A 与 B 合用 | 17.52 s | 22.12 s | 43.7% |

JSON 阶段中位数约 4.53～4.58 秒，保持稳定。每次均校验 22 个 JSON/Markdown 文件哈希，并逐对象确认全部原字段保留。额外比较了完整 Sheet 构建结果及包含检测诊断的正式 JSON 输出，也完全一致。

第二个样本为 T0202：37,749 个对象、18 个 Sheet。双方均省略 VLM，其他条件相同；基线与 AB 各测三次，38 个产物哈希一致。

| 变体 | Sheet/MD 中位耗时 | 总中位耗时 |
|---|---:|---:|
| 基线 | 3.29 s | 4.98 s |
| AB | 2.49 s | 4.14 s |

T0202 这一条件下没有说明区域，所以不执行标记重建；收益主要来自 B，不能视为 A 的第二份性能证明。它验证了第二种图纸上的输出等价性及图框归属优化。

## 最终保留的改动

1. `_mark`：先使用原有边界条件过滤线段，再计算对角分量、比较来源；填充标记的结果已确定时直接返回。没有改变距离、角度或状态判定阈值。
2. `add_frames`：每个图框计算一次已有容差，在其文字、线段和内部边界归属判断中复用。使用临时字典副本，不把缓存字段写入产物。
3. 删除 `dwg_extract.py` 的 962 行旧梁拓扑及 Drawing Text 切片生成器。仓库引用检查未发现外部调用，parser registry 直接注册 DWGParser。此删除减少维护代码，不作为导入提速的来源。

DWG parser 源文件总行数由 5,858 降至 4,894，净减少 964 行。没有新增生产实验开关、全局缓存、额外索引或几何启发式。10.2 的 JSON/Markdown 双份文字策略保持不变。

## 没有继续改的部分

- 不删除选项框、表格和旋转图框识别：它们仍服务于已确认需求，删除会改变解析含义。
- 不删除旧 JSON 分片读取器：它仍用于历史产物兼容，并有重组校验测试。
- 不为收益较小的对象关系表重复构建增加共享缓存，也不取消空间排序。
- 不修改 VLM 调用策略、提示词、摘要和 Embedding。此前正式导入中这些阶段仍消耗较多时间，本轮 CPU 提速不能替代完整导入测量。

标记分组仍有两两比较，JSON 输出仍需序列化完整数据；更大图纸上可以继续剖析。当前没有足够证据引入更复杂的空间查询结构、替代序列化库或新的兼容层。

## 验证与复现

相关 pytest 覆盖 DWG 坐标/旋转、图框、表格、标记、JSON 保全、并发、正式 Bundle 发布和 OVPack，共 212 项通过；Ruff 和 diff whitespace 检查通过。补充的干扰线段样例同时通过原实现和优化实现，验证来源身份包括块实例路径。

本地实验目录：`.local-data/dwg-v102-ablation-20260914/`。

- `baseline/`：本轮之前的十个 parser 文件、来源哈希、基线产物哈希及旧生成器引用检查。
- `runs/monitor-ablation.json`、`runs/t0202-ablation.json`：逐次耗时、执行顺序、产物一致性记录。
- `runs/full-pipeline-equivalence.json`：完整 Sheet 结果及正式诊断 JSON 的等价性核验。
- `summary.json`：汇总、代码行数及实验边界。
- `benchmark.py`：仅位于实验目录的变体切换与测量代码。

既有 OV 服务、已导入数据及冻结评测未修改。固定返回回放证明代码在这些输入上的结果等价，不证明 VLM 分区或答案本身正确，也不代表所有大型 DWG 都能获得相同比例的提速。
