# DWGParser：以空间分块为基线

**状态：当前独立工作树已实现 parser v9，验证范围为离线固定输入测试。** 旧工作树的 v7/v8 产物、配置与服务未被本轮改动。尚未用 v9 执行真实新导入、在线 VLM 验证或冻结 55 题评测，不能据此声称解析或答题效果改善。

## 目标与取舍

保留完整的、规范化后的 LibreDWG JSON，将明确的说明正文和独立表格整理为 Markdown，其余记录按空间邻近顺序切成预算内的小块。补充一份 Sheet 内图形资产目录 `assets*.md`，让小图的图号、标题和可见内容也能被检索。JSON 存储不以 asset 或 View 边界为前提。

基础链路是：**Sheet 划分 → 说明/表格 Markdown + 空间 JSON 分块 → 轻量 assets 导航**。精细 View 切片、每图专属目录和额外对象索引仍由消融结果决定。

| 保留的能力 | 收缩的设计 |
|---|---|
| 原始 DWG、完整原生记录及来源对应 | 不导出 `sheet.dwg`，不保留超大完整 `structure.json` 副本 |
| Sheet 作为 OV 最小检索单位 | 不把每个小图或空间块建成独立 Bundle |
| 说明/独立表格转 MD；图内标注保留 JSON | VLM 同时识别图形 asset 的可见标题、内容和范围，不扩成几何关系图 |
| 空间排序、预算检查和可逆分片 | 不按 View 建目录，不用 `shared/` 解决跨 View 归属 |
| 可检索的 `assets*.md` 导航 | 只指向现有分块，不为每个 asset 复制数据或建立 Bundle |
| 非空间数据、未知位置及跨 Sheet 数据保全 | 不把 `catalog/shared/unassigned` 三套目录作为默认接口 |

## 产物

```text
<dwg-document>/
├── <original-name>.dwg
├── manifest.json                 # OV 系统清单
├── metadata_00001.json           # 顶层信息、非放置定义、非图形记录等
├── chunks/                      # 文档级记录：跨 Sheet、框外或位置未知
│   └── chunk_00001.json
└── sheets/
    └── <sheet-id>/
        ├── manifest.json         # OV 系统清单
        ├── context*.md
        ├── assets.md             # 有图形资产时生成；图号/标题、内容、相关分片
        └── chunks/
            └── chunk_00001.json
```

文档级 `chunks/` 沿用同一分块格式，承接不能唯一放到某个 Sheet 的记录；不另建共享池或错误池。上述目录按实际数据生成，系统摘要文件仍由 OV 管理。

上图是正式 `bundle=true` 产物。普通 DWG 导入保留相同的 Markdown/JSON 数据布局，并用文档根下的小型隐藏文件 `.dwg-processing.json` 持久标识 DWG 处理边界；该文件只记录格式与来源身份，不登记全部分片、不建立 Atomic Resource Bundle，也不承担 Bundle 的不可变性约束。混合目录合并时保留此标记，后续重建仍能识别其中的 DWG JSON。正式 Bundle 继续使用系统 `manifest.json`。

`metadata` 表示数据作用域，不表示解析失败。明确没有放置位置的数据可进入 metadata；有空间意义但暂时无法定位的图元仍保留在文档级 chunks，并记录未知/`partial`。不做 View 切分本身不构成 `partial`。

## Sheet 内的 assets 导航

这里的 asset 是可独立识别的一组图形内容，通常以共同图号或标题为边界。用户附图中的“图五 斜梁、折梁配筋构造”可以包含多幅相关子图；“图六 梁侧面纵向构造筋和拉筋”连同其内部表格可以作为另一项。不另建子图层级树，也不把图内的附属表格误当成独立说明表格。

复用 Sheet 图像的 VLM 识别过程，在说明/表格区域之外提取 asset 的图号、原题名、简短可见内容概述和 bbox；不为每个 JSON 分片增加模型调用。提示词要求抄录可见标题、将同一图号下的子图与内部表格合并，读不清时留空，不补造图名、尺寸、材料值或构件关系。本轮没有新增 OCR 或原生文字交叉核对步骤，也没有用真实在线 VLM 验证分组与识字效果。图像概述用于导航，不能替代精确 CAD 数据证据。

JSON 分块写出后，本地根据 asset 范围、对象的实际放置及落盘文件计算映射，再生成 Markdown。VLM 不生成 chunk 编号。目录至少包含以下内容：

| 字段 | 用途 |
|---|---|
| Sheet 内唯一标识、原图号和标题 | 区分本 Sheet 的不同资产，保留原图命名 |
| 简短图像内容概述 | 使没有长篇说明的小图也具有可检索的内容 |
| 相关 JSON 分片及必要的文档级依赖 | 指向实际存在的文件；支持连续区间或多个分离区间 |
| 定位不完整说明（需要时） | 显式保留未知范围、不可读标题或未能绑定的部分 |

**相关分片不是独占边界。** 空间排序可能让同一 asset 对应多段文件，也可能让一个 chunk 含多个 asset 的对象。连续文件可显示为“00012–00018”；若实际还涉及“00031–00033”，须分别列出，不能压成“00012–00033”。这些编号仅示意展示格式，不是对附图已完成的分片定位。

保留可解析的相对文件路径；区间标签同时附带该段每个真实文件的链接，分页后仍可恢复完整清单。涉及的原生记录若被拆成多个 fragment，映射覆盖全部 part。重复块按放置实例计算相关性；定义或跨 Sheet 对象若在文档级，另列真实依赖路径，不声称 Sheet chunks 自包含全部几何。映射使用内存中的对象/实例→文件表，不新增持久化 `catalog/` 或资产数据库。

图内标题和标注摘录进目录，不代表正文已迁出 JSON，其原始字段仍保留。纯说明、纯表格 Sheet 本来没有图形 asset 是正常情况，不必生成空目录或标记覆盖不足；有图形但识别、标题读取或分片绑定不完整时，说明目录覆盖不足，仍完整保留数据和 Sheet。

`assets*.md` 使用 Markdown 配置的 token/字符上限，且估算 tokens 不超过 Embedding 输入预算的 80%；估算器与 Embedding 输入检查一致，标题、续页信息、链接与区间也计入。过长时按完整条目、链接或区间分页为 `assets_001.md` 等；单个 asset 跨页时保留 Sheet/asset 标识及完整范围，不截断链接、省略分片或依赖 Embedding 侧静默截断。

参见[基于附图的目录内容示例](examples/dwg-assets-navigation-example.md)。示例没有实际分块数据，因此不会伪造真实 chunk 区间。

## 模型处理边界

**入库链路中的 `chunks/*.json` 不做 Embedding，也不送给 VLM。** 文档级与 Sheet 级 chunks 都适用；metadata 等其他 DWG JSON 产物沿用同一只读证据策略。

| 输入/产物 | 自动模型处理 | Embedding |
|---|---|---|
| 临时 Sheet 渲染图 | VLM 辅助识别说明/表格区、图形 asset 的导航信息及已有的 Sheet 候选校验 | 不做 |
| Sheet `context*.md` | 沿用 Markdown 摘要链路 | 沿用现有索引链路 |
| Sheet `assets*.md` | 本地用图像识别结果和实际文件映射生成；可进入现有 Markdown 摘要链路 | 做，用于检索图号、标题及图像内容概述 |
| DWG JSON 产物 | 仅本地排序、切块、校验、登记和读取；不做 VLM 理解、改写、命名或摘要 | 不做 |

父目录递归处理也遵守该边界：不为 chunks 生成模型摘要，不把 JSON 内容拼进 Sheet/文档摘要，不自动将 JSON 转成 Markdown 后再送模型。`summary_files` 和 `include_files` 白名单只允许 Sheet `context*.md` 与 `assets*.md`；普通目录通过 DWG 处理标记、正式 Bundle 通过有效 Manifest 恢复这一规则。仅设置 `searchable=false` 不足以约束摘要路径。JSON 的排除在 A/B 两侧都保持一致。

`assets*.md` 的描述来自 Sheet 图像，分片映射由本地程序计算，不能通过将 chunks 内容交给 VLM 生成目录。摘要与检索由既有 Markdown 路径接入，不新增逐 asset 的二次图像解读流程；新增 Markdown 页带来的模型调用和耗时按实记录。

这里限制的是入库、自动加工及重建过程。问答阶段按需读取 JSON 作为证据的能力仍保留。JSON 的 token/字符预算只控制文件与读取大小，不代表会调用 Embedding API。

v9 将 assets 登记为可检索 Markdown，并将相同允许范围用于首次导入、重建、父目录递归处理及 OVPack 索引恢复。正文 `context*.md` 的路径由 `content_paths` 保存，导航由独立的 `asset_paths` 保存；摘要/索引使用两者并集，正文转存引用仍只使用 `content_paths`。图内标题出现在 assets 中不会使其原始字段从 JSON 删除。正式 Bundle 检索仍以 Sheet 为单位，命中的导航文件提供 asset 标识和实际分片链接。

这些保护依赖有效 DWG Manifest 或普通导入的处理标记，不因任意目录名叫 `chunks` 就生效。本轮通过离线替身和固定输入检查代码边界，未在另一工作树的服务上执行导入、重建或 OVPack 回读。

## 最小处理方式

1. 继续使用已有 Sheet 识别和文字阅读顺序逻辑，完整遍历 `OBJECTS` 及其他顶层字段。
2. 在同一 Sheet 图像识别过程中取得说明/独立表格区域及图形 asset 导航信息。已有的 Sheet 候选校验可保留；不新增一套验证模型。纯图纸没有说明/表格区域是正常结果，不能据此或因目录缺项拒绝 Sheet。
3. 对有放置位置的记录，用 bbox/中心点参与排序；排序仅决定存储位置，不改变原坐标。先复用现有最长轴递归分组，不为本轮同时引入网格、Morton 等多种算法。
4. 在每个 Sheet 内直接按空间顺序装块。跨 View 的长线、尺寸或文字仍是完整对象，按其位置进入一个块，不裁切、不复制为多份。跨 Sheet 或无法可靠归属的记录进入文档级 chunks。
5. 所有块执行同一预算检查，超大记录使用已有可逆分片。bbox 只是覆盖范围，块之间可以重叠；没有可靠位置时不伪造 bbox。
6. 根据已生成的分块构建 `assets*.md`，将其登记为可检索导航；该步骤不改变 JSON 的分块顺序或原始字段。

分块的 `records` 保存原生对象、必要的实例定位以及重组信息；存储目录表达作用域，实例记录携带可用的 bbox 与变换，原对象序号保持不变。原生块定义保留一份；重复 INSERT 保留原引用和变换，MD 来源等需要区分实例的场景使用插入路径。被多个实例复用的定义不能任选一次世界坐标代表自身，可留在文档级 metadata，由 Sheet 内的 INSERT 解引用。无需为了分块持久化另一套展开的几何图谱。

OV 系统 manifest 继续提供文件清单与哈希。读取器可以扫描小块恢复原对象或解析原生引用；暂不额外持久化 handle→文件的 catalog。若这一步确实造成读取成本或答题回退，再凭失败样例增加必要定位信息。

## 不能随目录一起删掉的约束

- 原始 DWG 字节不变；除已转入 MD 的正文外，保留全部原字段、类型、数组内容及顺序（包括顶点、控制点等）。空间排序只调整对象之间的存储次序，仍能凭原 `OBJECTS` 序号恢复原顺序；实例遍历不能替代完整原对象清单，未实例化的块定义也要保留。
- 正文实际写入 MD、且所有真实使用实例都被覆盖后，才可移除对应 JSON 字段。其他实例仍作图内标注或归属不明时保留原文；不同值的文本别名和原生表格结构同样保留。
- 原生引用、必要的实例来源与跨文件分片仍可解析、重组。去掉 `shared/` 不等于去掉块定义或把同一 handle 当成同一个放置实例。
- 每个 parser JSON 默认不超过 **2048 估算 tokens、6000 字符**，且不超过 Embedding 配置预算的 80%；metadata 和分片包装也计入。仅 OV 根/Sheet 的系统 `manifest.json` 豁免。
- 正式入库登记完整产物；DWG JSON 不进入 Embedding、VLM 或自动摘要，摘要与索引只允许 Sheet `context*.md` 和 `assets*.md`。正文来源引用与可检索文件清单分开。重建摘要、补建索引与 OVPack 回读也须遵守该边界。

## 如何决定简化是否成立

旧 v7/v8 产物与当前 v9 空间分块实现可以作为独立对照，但目前没有两者的 55 题比较结果，不能先断言“效果一样”。

先在测试中固定 DWG、Sheet 和说明/表格选择结果，只替换 JSON 组织，检查原字段、MD 正文、实例对应、引用和预算。随后沿用冻结的 55 题及已约定的模型、工具和超时重试规则，分别保留 A/B 独立语料与原始结果。

模型路由验收须捕获实际输入：JSON 产物及其父目录递归路径不能触发 VLM/Embedding，也不能混入模型摘要输入；允许的前置图像分区与 Markdown 调用单独计数。JSON 仍应完整保存并可直接读取。

离线测试检查注入的 asset 分组、非连续分片、多个 asset 共用块、大对象完整分片、重复 INSERT 和目录分页后的链接保全，并检查导航文件进入允许的索引范围。固定 Sheet 与说明/表格选择结果，改变资产边界、标题或在测试中省略目录时，JSON 原字段和分块结果保持一致。没有实际分块映射时不能输出猜测的编号范围。真实 VLM 能否正确识别图号组、检索模型能否通过标题或描述找到目标条目，仍需后续在线验证。

比较完整正确率、证据/关系绑定、导入耗时和读取成本。如果 MD、导航信息或索引也改变，明确称为端到端链路对照，不把全部差异归因于 JSON 排序。可在测试/评测中固定相同 JSON，对比有无 assets 导航；不增加生产实验开关。完整性与预算是硬门槛，更细的 View 切片、每图独占目录或持久化对象索引仍需由具体失败证明价值。

不为对照新增生产实验开关，不根据答案改 Gold，不把此前中途停止的运行或确定性重放当成新的正式得分。
