# Make DWG sheets the retrieval unit

**Status:** accepted; parser v9 implements spatial JSON storage and searchable asset navigation in the isolated worktree. Validation in this revision is offline only.

A DWG is ingested as a root v2 `kind=dwg` DWG Document Container that owns the unchanged source exactly once. The parser discovers Sheets from Paper Space Layouts and Model Space drawing frames, then generates a nested v3 `kind=dwg-sheet` Bundle for each Sheet; each Sheet Bundle uses `source_ref` to identify the shared source and is the minimum DWG `find_resource` result. Sheet identity comes from its source locator, while drawing number and title remain display metadata. This controlled nesting is the intentional DWG exception to the normal non-overlapping Bundle Boundary, and it supersedes the DWG package shape and spatial `Drawing Text Index` semantics in ADR-0011.

The preservation contract uses the complete normalized LibreDWG JSON as its intermediate `structure.json`. Confirmed prose and independent tables use the existing Markdown reading-order path; other native fields remain in bounded JSON. Coordinates are not rewritten. A prose field is removed only after its text is emitted to Markdown and all its placed uses are accounted for; any graphical or uncertain use keeps its native text. Original object order, block references and reversible fragments remain recoverable. New parses do not export `sheet.dwg` or persist a monolithic `structure.json`.

JSON chunks are read-accessible evidence. The processing contract excludes DWG JSON from embedding and automatic VLM interpretation, rewriting or summarization, including through parent-directory processing and rebuilds. The root and Sheet manifests inventory them with hashes; explicit Markdown allowlists govern model processing and indexing. Query-time JSON reading and VLM use on temporary Sheet images remain available. The existing v2/v3 system manifests are exempt from chunk budgets; all parser JSON and fragment envelopes are bounded. Uncertain placement and unsupported geometry remain preserved and explicitly uncertain. Rendered images are transient; display-encoding repairs apply only to that temporary representation.

The earlier v7/v8 artifacts and their services remain unchanged. Their per-View directories and `catalog/`, `shared/`, and `unassigned/` trees describe the previous implementation, not an architectural requirement. Historical validation results remain in [the implementation record](../design/dwg-parser-json-validation.md); they do not establish the quality of the v9 layout or its asset navigation.

## Spatial storage and asset navigation — parser v9

Use **Sheet + prose Markdown + spatially ordered JSON chunks**, with a lightweight searchable `assets*.md` navigation aid. The same Sheet-image recognition identifies prose, independent tables and graphical asset numbers/titles, visible-content descriptions and bounds. JSON grouping remains independent of those asset boundaries. After chunking, local code links each asset to actual related files; non-contiguous ranges, shared chunks and fragment dependencies remain explicit. An asset can group related views and an internal table under one title, without a new hierarchy or independent Bundle.

The Markdown allowlists include `context*.md` and `assets*.md`, so figure titles and descriptions can lead retrieval to the owning Sheet and its asset entry. `content_paths` identifies the transferred body, while `asset_paths` separately identifies navigation; summary/index selection uses their union. Prose provenance still refers only to `content_paths`; copying a figure title into navigation does not remove it from native JSON. Document-level `metadata_00001.json` and `chunks/chunk_00001.json` retain definitions, cross-Sheet objects and uncertain placement. This drops the three parser-specific auxiliary trees and per-View directories while retaining native identity, necessary references, bounded storage and OV system manifests.

Ordinary DWG ingestion persists a small `.dwg-processing.json` format/source marker, including when merged into a mixed directory, so later processing can recover the DWG Markdown allowlist. It is not an Atomic Resource Bundle, artifact inventory or immutability boundary. Formal Bundle ingestion continues to use its system manifests. Reindexing, parent processing and OVPack index restoration apply the DWG exclusion policy when a valid manifest or processing marker identifies the subtree; unrelated resources retain their existing behavior.

The [spatial-chunk implementation notes](../design/dwg-parser-spatial-chunks.md) define the layout and checks. The VLM prompt groups related subfigures and internal tables under one figure title; this revision adds no OCR cross-check and makes no real-VLM grouping or recognition accuracy claim. Finer View-based storage or persistent object-location indexes still require demonstrated benefit; the asset catalog is a reading aid rather than another storage partition. Comparisons use fixed inputs and test-side injection, not production experiment switches. No new real-source ingestion, live VLM evaluation or 55-question scoring was performed in this worktree revision.
